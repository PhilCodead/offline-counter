# Участие в разработке

Для исправления ошибки приложите сценарий воспроизведения. Существенные изменения поведения сначала обсудите в issue: какое ограничение они снимают и как должны работать.

## Подготовка изменений

1. Создайте ветку от `main`.
2. Ограничьте PR одной задачей. Изменения форматирования и обновления зависимостей оформляйте отдельно от исправлений поведения.
3. Для изменения логики добавьте проверку, воспроизводящую исходную проблему.
4. Запустите проверки из [руководства разработчика](docs/DEVELOPMENT.md#проверки).

Сохраняйте разделение между логикой подсчёта и Android API. Изменения распознавания проверяйте на повторных запусках, пересекающихся экранах списка и прерванной прокрутке. Используйте вымышленные данные.

Для изменений интерфейса проверьте обе темы, увеличенный размер шрифта и расположение панели у краёв экрана. В описании PR укажите устройство и выполненные проверки; приложите скриншоты, если они помогают оценить результат.

## Описание pull request

Объясните проблему, новое поведение и способ проверки. Отдельно укажите ограничения, которые не удалось проверить. Если изменение влияет на пользователя, добавьте запись в [CHANGELOG.md](CHANGELOG.md).

Не добавляйте в репозиторий ключи подписи, пароли, локальные пути и файлы с персональными данными. Порядок выпуска описан в [docs/RELEASE.md](docs/RELEASE.md).
